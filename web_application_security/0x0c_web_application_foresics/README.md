# Web Application Forensics - Attacker Service Analysis

## Overview

This project focuses on basic digital forensics techniques used to investigate authentication logs and identify how an attacker gained access to a Linux system.

The main goal of this task is to analyze an `auth.log` file, identify suspicious authentication activity, and determine which service was used by the attacker to access the server.

## Learning Objectives

By completing this task, you should be able to:

- Understand the purpose of Linux authentication logs.
- Identify successful and failed login attempts.
- Recognize SSH authentication events.
- Use command-line tools such as `grep`, `awk`, `sort`, and `uniq`.
- Extract useful information from large log files.
- Understand the difference between the SSH protocol and the `sshd` daemon.
- Build a simple Bash script that analyzes log data automatically.

## Files

- `auth.log` - Linux authentication log used for forensic analysis.
- `0-service.sh` - Bash script used to analyze the log and identify the service involved in the attack.

## Investigation Process

The investigation starts by examining the authentication log:

```bash
head -n 20 auth.log
```

To inspect SSH-related events:

```bash
grep 'sshd' auth.log
```

To search for successful password authentication:

```bash
grep 'Accepted password' auth.log
```

A typical successful SSH login entry may look like this:

```text
May 16 08:26:06 app-1 sshd[4894]: Accepted password for user from 192.168.1.10 port 61474 ssh2
```

Important fields include:

- `sshd` - the SSH server daemon that handled the connection.
- `Accepted password` - authentication succeeded.
- `user` - the account used to log in.
- `192.168.1.10` - the source IP address.
- `ssh2` - SSH protocol version 2.

## Detecting Suspicious Activity

Failed SSH authentication attempts can be inspected with:

```bash
grep 'sshd' auth.log | grep 'Failed'
```

Invalid usernames can be inspected with:

```bash
grep 'sshd' auth.log | grep 'Invalid'
```

The number of failed attempts can be counted with:

```bash
grep 'sshd' auth.log | grep -c 'Failed'
```

A large number of failed or invalid authentication attempts followed by a successful login may indicate a brute-force or password-guessing attack.

## Log Analysis with awk, sort, and uniq

The following tools are useful when analyzing large logs:

### grep

Filters lines containing a specific pattern.

```bash
grep 'sshd' auth.log
```

### awk

Extracts specific fields from each line.

```bash
grep 'sshd' auth.log | awk '{print $6}'
```

### sort

Sorts output so identical values appear next to each other.

```bash
grep 'sshd' auth.log | awk '{print $6}' | sort
```

### uniq -c

Counts repeated values.

```bash
grep 'sshd' auth.log | awk '{print $6}' | sort | uniq -c
```

### sort -nr

Sorts numerical results from highest to lowest.

```bash
grep 'sshd' auth.log | awk '{print $6}' | sort | uniq -c | sort -nr
```

## Bash Script Requirements

The script should:

- Start with:

```bash
#!/bin/bash
```

- Accept the log file as its first argument:

```text
$1
```

This allows the script to be executed like:

```bash
./0-service.sh auth.log
```

Instead of hardcoding a single file name, using `$1` makes the script reusable with other log files.

The script should also be executable:

```bash
chmod +x 0-service.sh
```

## Conclusion

The authentication logs show that the system was accessed through the SSH service.

The evidence is found in entries generated by the `sshd` daemon, including successful authentication events such as:

```text
Accepted password
```

This task demonstrates how simple Linux command-line tools can be combined to perform practical forensic log analysis and reconstruct attacker activity.
